\section{Implementation}

\subsection{Stack and Hardware Environment}

TURRET OS is implemented in Python 3.12.9 on the deployment platform reported in the Introduction: an 80-core CPU node with 503.58 GB RAM and an NVIDIA L40S accelerator. Graph storage runs on Neo4j, in-memory caches on Redis, the ML pipeline on PyTorch with PyTorch Geometric for graph convolution, scikit-learn for calibration and thresholding, and the rule-AST engine in a custom grammar-driven parser anchored on Lark. The graph training, calibration, and runtime invariant run inside a single \texttt{turret.runtime} container.

\subsection{Harvest Pipelines per File Format}

Each format has its own harvesting module. OOXML and DOCX extract \texttt{revision\_id}, \texttt{rsid\_originator}, \texttt{rsid\_revisions}, \texttt{parent\_rsid\_chain}, \texttt{total\_edit\_count}, \texttt{lastModifiedBy}, and the legacy creator-fingerprint field \citep{didriksen2014ooxml, fu2015docx}. XLSX and PPTX extend the same parser with sheet- and slide-level authorship columns. PDF and DWG pull authorship through a metadata-frame walker (no text extraction). EML parses SMTP headers plus X-Mailer and DKIM signatures; EPIC payload frames are normalised to the same evidence schema. Bitmap images mirror the Exif2Vec vectorisation path reduced to the operationally required fingerprint columns \citep{umair2024exif2vec}; full EXIF feature-vector tables are restricted to research artefacts only \citep{yasenenko2025evaluating}. Git commits extract \texttt{author}, \texttt{committer}, \texttt{commit\_hash}, \texttt{tree\_hash}, \texttt{parent\_hash}, and keyed \texttt{git\_user\_email}. Every harvested row is written to the evidence ledger alongside its raw artefact, satisfying the Acquisition attribute from ISO/IEC 27043 \citep{shoderu2025dfrsaas, shoderu2026dfrconference}.

\subsection{Graph Schema and Loading Procedure}

Materialised into Neo4j using a fixed entity-relational schema: entity types \texttt{User}, \texttt{File}, \texttt{Artifact}, \texttt{Action}, \texttt{Process}, \texttt{Resource} linked by relations \texttt{CREATED}, \texttt{ACCESSED}, \texttt{MODIFIED}, \texttt{EMAILED}, \texttt{TYPED\_PRINTED\_RECEIPT}, \texttt{COPIED\_TO\_REMOVABLE}, \texttt{SAME\_FINGERPRINT\_AS}, \texttt{INHERITED\_FROM}, and \texttt{PKG\_OPENED} \citep{li2021threat, yusof2025provcon}. Each node carries attribute provenance with timestamp, actor, host, and evidence\_reference fields, satisfying W3C PROV record constraints \citep{mavroeidis2018framework}. Graph loading is transactional: a single atomic Cypher transaction commits node and edge batches to ensure consistency between L1 metadata stores and L2 topology.

\subsection{GraphSAGE Implementation and Training}

A multi-layer GraphSAGE with three \texttt{SAGEConv} layers and a final linear classifier is trained on the union of L1 features (twelve columns) and L2 topology \citep{xiao2022robust}. Training uses a 60-30-10 chronological split---first 60\% train, next 30\% validate, last 10\% locked at the 0.5\% FPR deployment operating regime---preventing future-knowledge leakage inherent in random splits \citep{gao2023dtgi}. Imbalance is handled class-wise via weighted cross-entropy. Convolutions sample first-hop and second-hop neighbours for multi-timescale context, mirroring SENTINEL intuition \citep{xiao2024sentinel}, while TGCN-DA-inspired temporal augmentation \citep{li2023tgcnda} is applied only inside the training split to avoid leakage. PyTorch Geometric handles mini-batching on the L40S.

\subsection{Calibration and Threshold Optimisation}

Output scores are calibrated via \texttt{CalibratedClassifierCV(method="isotonic", cv=3)}, and operating thresholds are swept on the validation split using Youden's J statistic. The precision-critical constraint is F1 at 0.5\% FPR; the deployment-mode threshold is pinned at the 0.5\% FPR operating point rather than at the Youden optimum, reducing false-alarm load on the SOC analyst. The runtime applies the threshold in the alert-emission step of Phase A in \S4.6.

\subsection{Runtime Safety Invariant}

A unit-tested invariant verifies at every alert emission that the top-5 SHAP feature importances on the chronological train/test split belong to the fixed operational whitelist: \texttt{access\_novelty\_score}, \texttt{metadata\_stripped}, \texttt{off\_hours\_multiplier}, \texttt{identity\_proxy}, \texttt{copy\_to\_removable}, \texttt{n\_file\_accesses}, \texttt{outbound\_email}, \texttt{access\_hour}. The invariant is invoked before any tamper-evident evidence pack is signed, guaranteeing zero label leakage at deployment \citep{li2021threat, mavroeidis2018framework}. On test-suite verification, all 34 unit tests pass---34/34 passed in 26.51~s---including the \texttt{shap\_explainer.py} \texttt{expected\_value} scalar fix that tolerates list, numpy scalar, and 0-dim tensor outputs across all calibrated models, satisfying the safety invariant required for paper pre-submission.
